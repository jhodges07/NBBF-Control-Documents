Node-Based Budget Framework (NBBF)

AUTHORITATIVE HOME
==================================================

This CONTROL answers:

HOW ARE AUTHORIZED NODES COMPOSED INTO AN OPERATING NBBF SYSTEM?

CONTROL 01 answers:

WHAT IS A NODE AND WHAT RELATIONSHIPS CAN EXIST?

CONTROL 00 answers:

WHAT IS NBBF ROOT AUTHORITY?

A System Structure is not a new Node type.

A System Structure is an authorized composition of Nodes and their lawful
structural relationships, using ontology established by CONTROL 01.

Concise vocabulary: CONTROL 02.
This CONTROL SHALL NOT create competing definitions of Node, Human Owner,
Decision Node, Assembly Node, Detail Node, Support Node, or Root Node.

==================================================
1. PURPOSE
==================================================

This document establishes the System Structure Model of NBBF.

Its purpose is to ensure that authorized Nodes may be assembled into a
coherent governmental operating system without destroying Node identity,
human accountability, Decision-Node attribution, funding traceability,
Signal pathways, review pathways, auditability, Exit boundaries, or
recovery referral pathways.

This CONTROL defines how structural relationships are represented at the
system-composition level. It does not define what a Node is.

This CONTROL does not create a second ontology, Signal system,
property-rights system, exit system, republican-government model, review
calendar, cost/value system, audit system, recovery system, legislative
procedure, API system, procurement system, or education framework.

==================================================
2. SYSTEM STRUCTURE DEFINED
==================================================

A System Structure is an authorized composition of Nodes and their lawful
structural relationships.

A System Structure SHALL:

• Preserve Node identity
• Preserve accountable human ownership
• Preserve Decision-Node attribution
• Preserve lawful jurisdiction
• Preserve funding traceability
• Preserve Signal pathways
• Preserve review pathways
• Preserve auditability
• Preserve Exit / Disengagement boundaries
• Preserve recovery referral pathways
• Avoid hidden authority
• Avoid hidden pooled responsibility
• Avoid structural arrangements that make accountability impossible

System composition SHALL NOT create authority merely because components
are digitally connected, administratively grouped, mapped, visualized,
or stored together.

Authorization originates from lawful governmental authority and the
applicable NBBF CONTROLs. Connection is not authorization.

==================================================
3. CONSUMPTION OF CONTROL 01 ONTOLOGY
==================================================

This CONTROL uses, and does not replace, CONTROL 01.

The following remain CONTROL 01:

• What constitutes a Node
• Node types, including Root Node as a Node-hierarchy type, Branch Node,
  Program Node, Operational Node, Support Node, and Legacy Node
• Decision Node, Assembly Node, Detail Node, and Support Node classes
• Human Node and Human Owner
• Required Node properties
• Node relationships as ontology
• Node hierarchy as ontology
• Node lifecycle ontology
• Ownership ontology

This CONTROL MAY identify which authorized Nodes, of types already
defined by CONTROL 01, participate in a System Structure.

This CONTROL MAY identify which lawful parent, child, or participating
relationships already permitted by CONTROL 01 are in force for system
operation.

This CONTROL SHALL NOT:

• Create a new Node type
• Redefine Node classes
• Redefine Human Owner, Human Node, Decision Node, Assembly Node,
  Detail Node, Support Node, or Root Node
• Convert a System Structure into a substitute Node
• Treat a department, office, committee, software model, or pooled fund
  as a Node

A composed system remains a composition of identifiable Nodes.

==================================================
4. SYSTEM COMPOSITION
==================================================

Authorized Nodes MAY be composed into a larger NBBF governmental system
only where that composition preserves the requirements of Section 2.

Composition groups Nodes for system operation. It does not dissolve them.

A System Structure SHALL identify, at minimum:

• The system boundary
• The participating Nodes
• The Human Owner of each participating Node, as required by CONTROL 01
• The Decision Node or Decision Nodes to which material system decisions
  are attributable, as required by CONTROL 01 and applied by CONTROL 03
• The lawful jurisdiction of the system
• The structural relationships among participating Nodes
• The visible structural dependencies among participating Nodes

Grouping SHALL NOT destroy Node identity.

An administrative label, org chart, software folder, digital twin, budget
book, or dashboard MAY describe a System Structure. None of those artifacts
is the System Structure, and none of them creates NBBF authority.

==================================================
5. SYSTEM BOUNDARIES
==================================================

A System Structure SHALL have an identifiable boundary.

The boundary SHALL make it possible to determine:

• Which Nodes are inside the system
• Which Nodes are outside the system
• Where the system meets another system
• Where the system meets an applicable Decision Node
• Where the system meets taxpayers and other lawful observers, subject to
  controlling lawful authority

A boundary SHALL NOT be used to hide participating Nodes, Human Owners,
Decision-Node attribution, funding, Signals, review, audit, Exit, or
recovery pathways.

A system boundary is a composition fact. It is not a new ontology type.

==================================================
6. STRUCTURAL RELATIONSHIPS AND DEPENDENCIES
==================================================

At the system-composition level, structural relationships among Nodes
SHALL be represented so that a reviewer can see how the system operates
without consulting an undocumented custom, inaccessible process, or
opaque administrative mass.

This CONTROL MAY represent:

• Parent and child relationships already permitted by CONTROL 01
• Participating relationships among Nodes that jointly constitute a
  system without becoming a single Node
• Structural dependencies, including support or enabling relationships
  already permitted by CONTROL 01
• Interfaces between a system and an applicable Decision Node
• Interfaces to Signal, review, audit, Exit, and recovery pathways owned
  by other CONTROLs

Dependencies SHALL be visible.

A hidden dependency is a structural defect.

Visibility of a dependency does not transfer ownership, create funding
authority, create Signal operating rules, or create Exit procedure.

CONTROL 01 remains the home for Support Node collapse behavior and other
ontology of dependency types. This CONTROL requires that whatever
dependencies exist in a composed system be identifiable at the system
level.

==================================================
7. STRUCTURAL DECOMPOSITION
==================================================

Root CONTROL 00 requires that failure become visible while still small
enough to correct.

A governmental System Structure SHOULD be decomposed into sufficiently
bounded Nodes so that:

• Performance can be observed
• Failure can be localized
• Accountability can be attributed
• Signals can identify the affected structure
• Cost and value can be measured under CONTROL 06
• Audit can isolate the affected area under CONTROL 07
• Corrective action does not unnecessarily destabilize unrelated Nodes
• Exit or recovery can occur at the appropriate lawful boundary under
  CONTROL 00D or CONTROL 08 as applicable

This CONTROL does not create numeric Node-size, headcount, dollar, or
span-of-control limits.

Decomposition is a structural obligation of composition. It does not
redefine Node ontology.

A System Structure SHALL NOT be composed as one opaque high-level mass
whose failure can be observed only as a 50,000-foot system event.

Failure of one identifiable Node SHOULD remain distinguishable from
failure of the whole system, except where CONTROL 01 already provides
that collapse of a parent Decision Node collapses dependent child Nodes.

This CONTROL SHALL NOT redefine that ontology. It SHALL preserve the
ability to see which composed relationships are affected.

==================================================
8. ANTI-BIG-POOL STRUCTURE
==================================================

An opaque system-wide pool can destroy meaningful accountability.

This is a structural rule of composition. Property and pooling rights
remain CONTROL 00C.

System composition SHALL NOT silently merge:

• Authority
• Ownership
• Funding
• Performance
• Signals
• Audit responsibility
• Failure

into an indistinguishable administrative mass.

A System Structure MAY group related Nodes. Grouping is not pooling.

No System Structure MAY:

• Treat the system label as a substitute Node
• Hide which Node is responsible for a funded purpose
• Hide which Human Owner is accountable
• Convert many obligations into one unattributable responsibility
• Use system composition to create pooling authority, compulsory pooling,
  or consent rules owned by CONTROL 00C

This CONTROL SHALL NOT duplicate CONTROL 00C operating doctrine,
including consent, traceability of pooled property, taxation-as-pooling,
or pooling-exit principles.

Ontology constraints against pooling inside a Node remain CONTROL 01.
This CONTROL extends the anti-opacity requirement to system composition
without occupying those homes.

==================================================
9. AUTHORITY PATHWAY
==================================================

A composed NBBF system SHALL make the delegated authority pathway
structurally identifiable.

The structure SHOULD permit a reviewer to determine:

• Where authority originated
• Which Node received it
• Which Human Owner is accountable
• Which Decision Node authorized material decisions
• Which subordinate Nodes execute the work
• Which Signals relate to the structure
• Which review cycle applies
• Which audit findings apply
• Which Exit or recovery pathways may be implicated

This CONTROL SHALL NOT invent constitutional authority.

Republican-government application of delegated authority, representation,
and jurisdictional responsibility: CONTROL 03.

Legislative Decision-Node interface mechanics: CONTROL 10.

Node ontology of Human Owner, Decision Node, and authority-chain parent:
CONTROL 01.

A System Structure that cannot expose this pathway is structurally
noncompliant.

Hidden authority is not cured by a digital model, an org chart, or an
administrative title.

==================================================
10. FUNDING STRUCTURE
==================================================

This CONTROL MAY represent structural relationships involving funding.

A structural representation of funding SHALL preserve the ability to
identify which Node is responsible for the funded purpose.

This CONTROL SHALL NOT redefine:

• Property or pooling — CONTROL 00C
• Cost or Value — CONTROL 06
• Recovery or clawback — CONTROL 08
• Competitive Node Procurement — CONTROL 12, reserved; undrafted; no
  live CONTROL file

This CONTROL SHALL NOT create tax doctrine.

Funding lines, allocations, or contractor-payment relationships MAY appear
in a System Structure only as composition facts that keep the responsible
Node identifiable.

Appearance of a funding relationship in a System Structure does not
authorize spending, create a tax, create a pool, determine Cost or Value,
or determine recoverable value.

==================================================
11. SIGNAL STRUCTURE
==================================================

This CONTROL MAY identify where Signal pathways connect to system
components.

CONTROL 00B owns Signal operating doctrine.

This CONTROL SHALL NOT redefine:

• Reporting rights
• Signal lifecycle
• Suppression
• Escalation
• Evidence
• Close-out
• Interference

Definition of “Signal”: CONTROL 02.

A System Structure SHALL NOT intentionally hide the Node to which a
Signal belongs.

Structural Signal associations required of every Node remain CONTROL 01.
This CONTROL requires that those associations remain followable across
the composed system.

This CONTROL does not create a second Signal system.

==================================================
12. REVIEW, AUDIT, AND RECOVERY INTERFACES
==================================================

This CONTROL MAY expose structural interfaces to:

• CONTROL 05 — review and reauthorization
• CONTROL 07 — audit and performance
• CONTROL 08 — recovery and clawback

The System Structure Model SHOULD make it possible to identify which
Nodes and relationships are affected by those processes.

This CONTROL SHALL NOT absorb their procedures.

CONTROL 05 remains the review clock. This CONTROL SHALL NOT create
another calendar, review-due date system, or reauthorization cycle.

CONTROL 07 remains the home for audit procedure and performance
findings. This CONTROL SHALL NOT create audit methods, variance
doctrine, or performance tiers.

CONTROL 08 remains the home for recovery and clawback operating
mechanics. This CONTROL SHALL NOT create recovery formulas, collection
procedures, contractor-recovery systems, penalties, tribunals, or
offices.

A System Structure MAY show that a Node, relationship, or subsystem is
subject to review, audit, or recovery. Showing that interface is not
conducting the process.

==================================================
13. EXIT AND DISENGAGEMENT BOUNDARIES
==================================================

CONTROL 00D owns Exit and Disengagement.

This CONTROL MAY represent structural Exit boundaries and dependencies.

This CONTROL SHALL NOT create a second Exit procedure.

A system SHALL NOT be structured solely to make an otherwise authorized
Exit practically impossible through unnecessary structural entanglement.

This CONTROL does not expand legal Exit authority beyond CONTROL 00D.

Structural exit-condition fields remain CONTROL 01.

System restructuring SHALL NOT silently erase an existing Exit, recovery,
Signal, audit, review, or accountability record.

==================================================
14. LEGISLATIVE DECISION-NODE RELATIONSHIP
==================================================

CONTROL 10 owns the Legislative Decision-Node interface.

This CONTROL MAY represent the structural relationship between a
governmental system and an applicable Decision Node.

This CONTROL SHALL NOT define legislative procedure.

This CONTROL SHALL NOT create legislative authority.

Decision Node ontology: CONTROL 01.
Republican-government application: CONTROL 03.
Review calendar: CONTROL 05.

A System Structure MAY identify which Decision Node authorizes material
system decisions. It SHALL NOT conduct, replace, or automate that
authorization.

==================================================
15. LEGACY AND SEALED STRUCTURES
==================================================

CONTROL 09 — Legacy and Sealed Nodes remains RESERVED and undrafted.

Specialized structures MAY later require treatment under CONTROL 09 once
that CONTROL is authorized.

This CONTROL MAY acknowledge that a participating Node is a Legacy Node
as already classified by CONTROL 01, or that classification or sealing
may restrict visibility.

This CONTROL SHALL NOT draft Legacy or Sealed Node operating doctrine.
This CONTROL SHALL NOT occupy CONTROL 09.

Classification or sealing MAY restrict visibility. It SHALL NOT eliminate
the requirement that a System Structure remain attributable to identifiable
Nodes and Human Owners to the extent required by controlling lawful
authority and applicable NBBF CONTROLs.

Classified Signal operating rules: CONTROL 00B.
Exit of sealed or classified Nodes: CONTROL 00D.

==================================================
17. HUMAN AUTHORITY
==================================================

No digital System Structure Model SHALL replace human or constitutional
authority.

Software MAY represent structure.

Artificial intelligence MAY analyze structure.

Artificial intelligence MAY identify apparent structural inconsistencies.

Artificial intelligence SHALL NOT create authority merely by generating
or modifying a structural model.

Human accountability remains governed by CONTROL 00 and CONTROL 01.

A generated, inferred, or automatically rearranged model is not
authorization, reauthorization, Node creation, Exit, recovery, or
legislative decision.

==================================================
18. JURISDICTION
==================================================

This CONTROL is jurisdiction-neutral.

The same composition principles apply at every lawful republican level of
government.

This CONTROL MAY model:

• State government
• County government
• Municipal government
• Township government
• School districts
• Special districts
• Other lawful taxpayer-funded jurisdictions

INFORMATIVE: these examples explain jurisdiction neutrality. They do not
create jurisdiction-specific governmental authority.

This CONTROL SHALL NOT create Kansas-specific, federal-specific, or other
named-jurisdiction operating authority.

Republican-government application: CONTROL 03.

20. PROCUREMENT BOUNDARY
==================================================

This CONTROL SHALL NOT define:

• Subcontractor qualification

==================================================
21. ENFORCEMENT
==================================================

This CONTROL owns system-composition rules.

Structural noncompliance includes:

• Hidden structural authority
• Unattributable structural responsibility
• Composition that destroys Node identity
• Composition that prevents required accountability
• Structural concealment of funding or performance pathways
• Unauthorized structural merging of responsibilities
• Structural interference with required Signal, review, or audit pathways
• Structuring a system solely to make authorized Exit practically
  impossible through unnecessary entanglement
• Treating this CONTROL as Node ontology, Signal operations, pooling,
  Exit, review calendar, cost/value, audit, recovery, legislative
  procedure, API mechanics, procurement, NBEF, or Root authority
• Treating a digital model as authority

Detection MAY occur through:

• Authorized NBBF CONTROL stewardship under CONTROL 00
• Signals under CONTROL 00B
• Review under CONTROL 05
• Audit under CONTROL 07

Detailed audit procedure: CONTROL 07.
This CONTROL does not create an enforcement agency, tribunal, board,
criminal penalty, civil penalty, or new governmental power.
